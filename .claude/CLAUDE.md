# Social Space project rules

## Shipping changes

1. Work on your own branch in your own worktree so parallel sessions don't collide.
2. When the change is done (typecheck, tests, and the app was actually run), commit or merge it onto `dev`.
3. Releasing is merging the one standing `dev` -> `main` PR. The installed app builds new `main` commits and
   offers Restart to update (or Ava installs it, see below). Merging that PR needs Nate's go-ahead.
4. Bump the version for every change that reaches `main` (PATCH for fixes, MINOR for features), in
   `package.json`, `package-lock.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` and `Cargo.lock`.
5. Release builds only through `npm run tauri:build`, which refuses anything but a clean `main`.

## Worktrees: you made it, you remove it

Whoever creates a worktree owns it. Finishing a change means it is on `dev` and its worktree and branch are gone:
`git worktree remove <path>` then `git branch -d <branch>`. Never remove someone else's unmerged worktree, and
never remove `D:\Projects\SocialManager-release` (the installed app's source folder). A weekly job
(`%USERPROFILE%\.cargo\worktree-janitor.ps1`, after the Sunday cargo sweep) removes merged, clean worktrees that
were left behind and lists the rest for their owners.

## Updates are managed by Ava

Ava installs updates through the hub update contract (`--version --json`, `--update check|apply|rollback --json`,
marker `%APPDATA%\com.socialmanager.desktop\hub-managed.json`; see Ava's `docs/hub-module-spec.md`). Keep every
part of it working. Every Tauri command must also be listed in `src-tauri/build.rs` and
`capabilities/default.json`, or the installed app rejects it.

## How this repo works

- Social Space is a Tauri 2 desktop app: a React 19 + TypeScript front end in `src/` (Vite, vitest) and a Rust
  back end in `src-tauri/src/`. The workspace (brands, accounts, videos, post details) is one JSON document:
  `lib.rs` defines it (`Workspace`) and `src/model.ts` mirrors it, so a new field goes in both, and old
  workspaces must still load (unknown or missing fields never lock the user out).
- The UI never calls `invoke` from a component. Each area has a `*Service.ts` (e.g. `instagramService.ts`,
  `queueService.ts`) that wraps its commands and refuses outside the desktop app (`desktopOnly()`); hooks
  (`use*.ts`) hold the state. Components live flat in `src/`, pages in `src/pages/`, the assistant in
  `src/assistant/`.
- A Tauri command lives in its feature's Rust module and is registered in three places: `generate_handler!` in
  `lib.rs`, the command list in `src-tauri/build.rs`, and `src-tauri/capabilities/default.json`. A test in
  `lib.rs` fails when `build.rs` and the handler list disagree; commit the `src-tauri/gen/schemas` and `permissions/autogenerated` files the build regenerates.
- Secrets go to Windows Credential Manager (`account_passwords.rs`, `backup.rs`), never into the workspace file.
- Social APIs: Instagram (Meta API, `instagram.rs` + `instagram_login.rs`), YouTube/TikTok (`social_connect.rs`),
  X (`x_integration.rs`); video generation is provider-neutral in `video_gen.rs` and `video_sources.rs` (Kling,
  Grok). The assistant, Suggest buttons and picture maker call xAI Grok in `grok_ai.rs` with the key of the Grok
  video source (`video_sources::xai_key`). Partner review is `review.rs` + `website/` (Firebase site `socialspace-review`).
- Self-update and Ava's hub contract: `updater.rs`, `hub.rs`, `src/AppUpdates.tsx`, `src/updateService.ts`.
- Checks: `npm run typecheck`, `npm test`, and `cargo test --locked` in `src-tauri`.

## Playbooks

- **Add a Tauri command:** write it in the feature's `.rs` module, register it in `lib.rs`, `build.rs` and
  `capabilities/default.json`, wrap it in the feature's `*Service.ts`, test both sides. Example: `f05a77e`.
- **Add a workspace field:** add it to `lib.rs` and `src/model.ts` as optional, default it on load, add a test
  that an old workspace without it still loads. Example: `ce8dbf9`.
- **Ship:** bump with `npm run app-version -- X.Y.Z` (keeps package.json, tauri.conf.json, Cargo files in step),
  run the checks, run the app, merge to `dev` (see Shipping changes above).

## Finding your way (repo context kit)

The `repoctx` MCP tools serve this repo's map and memory. Orient with them instead of listing folders or
opening files to see what is there:

1. `recall` the question first. Saved answers say FRESH (the code they cite is unchanged) or STALE.
2. `repo_map` with the task as `focus`, or `overview` from the root and drill down. `find_symbol` for a
   definition, `feature` for every layer a feature touches.
3. Read only what those point at.

Leave the map better than you found it, in the same commit as your change: `remember` an answer that took real
searching (cite `path#Symbol`), `set_summaries` for a file or folder you had to read to understand, and
`add_feature` when you trace a feature across layers. They are saved in `.claude/context/`.
Without MCP, the same commands run as `python D:\Projects\repo-context-kit\repoctx.py <command>` (`--help`).
