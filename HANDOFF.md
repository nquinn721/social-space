# Social Space handoff

Written 2026-11-16 at version 0.30.5. This file is for anyone (person or AI) picking up the project. It has no
passwords or keys. Secrets live only in Windows Credential Manager on Nate's PC.

## 1. What the app is

Social Space is a Windows desktop app that Nate (SoftWings LLC) uses to run several faceless social brands. It
creates and stores each brand's social accounts, makes short videos with AI, writes the captions, and posts each
video to every social the brand has: TikTok, YouTube (Shorts), X, Instagram (Reels) and Facebook (Reels).

- Repo: `nquinn721/social-space`. Nate's checkout is `D:\Projects\SocialManager`.
- Stack: Tauri 2. The front end is React 19 + TypeScript (Vite, vitest) in `src/`. The back end is Rust in
  `src-tauri/src/`. The installer is NSIS.
- Checks: `npm run typecheck`, `npm test`, and `cargo test --locked` in `src-tauri`. Rust only builds on Windows
  (Credential Manager, WebView2), so run `cargo test` on Nate's PC.

## 2. Architecture rules that bite

- **Workspace = one JSON document.** Brands, accounts, videos and post details are one document. It is defined
  twice: `Workspace` in `src-tauri/src/lib.rs` and the mirror in `src/model.ts`. A new field goes in both, as
  optional, with a default on load. The Rust structs are typed, so a field missing in Rust is silently dropped
  on save. Old workspaces must always still load.
- **Tauri commands are registered in three places:** `generate_handler!` in `lib.rs`, the list in
  `src-tauri/build.rs`, and `src-tauri/capabilities/default.json`. A test in `lib.rs` fails if they disagree.
  Commit the regenerated `src-tauri/gen/schemas/*` and `permissions/autogenerated` files. Commands that open a
  window must be `async fn`, or WebView2 deadlocks and the window stays blank.
- **No `invoke` in components.** Each area has a `*Service.ts` wrapper (e.g. `instagramService.ts`,
  `postingService.ts`) that refuses outside the desktop app (`desktopOnly()`). Hooks (`use*.ts`) hold state.
  Components are flat in `src/`, pages in `src/pages/`, the assistant in `src/assistant/`.
- **Secrets** only go to Windows Credential Manager (`account_passwords.rs`, `backup.rs`, Facebook Page tokens
  under `social-manager-facebook-page`), never into the workspace file.
- **Repo context kit gates** (see `CLAUDE.md`):
  - Every new screen or setting goes in `.claude/context/features.json`.
  - Each branch writes `.claude/context/changes/<branch>.json`.
  - `python .githooks/repoctx-check.py check` must pass.
  - Never bypass the hooks.

## 3. Branching, releasing, updating

- All work goes on `dev`, with no per-feature PRs. Release by opening the one PR from `dev` to `main` and
  merging it. Nate's standing rule is **always release**: as soon as work is finished on dev, merge to main.
- Bump the version on every release with `npm run app-version -- X.Y.Z`. That keeps `package.json`,
  `package-lock.json`, `hub-app.json`, `tauri.conf.json`, `Cargo.toml` and `Cargo.lock` in step. Use PATCH for
  fixes and MINOR for features.
- **Self-update** (`updater.rs`, `AppUpdates.tsx`, `updateService.ts`):
  - The installed app watches `main` and builds it in the background in
    `%LOCALAPPDATA%\com.socialmanager.desktop\updates\build`.
  - The sidebar then shows "Update ready", and Nate presses Restart.
  - `npm run tauri:build` refuses anything but a clean `main`.
- Nate's assistant hub "Ava" can also install updates through the hub contract in `hub.rs`
  (`--version --json`, `--update check|apply|rollback --json`). Keep it working.
- Install on another PC: clone, then `npm start` (`scripts/install.mjs`). For development use `npm run dev:app`.
- Never launch the app through an AI "computer use / open application" tool. It then runs inside that tool's
  sandbox. Nate opens it from the Start menu.

## 4. Brand model

- A **Brand** (e.g. "Massage with Mia") **is** the account on each social: one account per social, named after
  the brand. No profile may be named "softwings". Nate expects about 5 or 6 brands.
- Categories or segments (e.g. bunny videos, goat videos) live inside a brand and post to that brand's accounts.
- UI: the sidebar has Overview, Brands, Inbox, Updates and Settings. Each brand page has the tabs Posts, Series
  and Accounts.
  - Accounts shows one line per social with a status, Sign in or Reconnect, View, and Details.
  - Each video has Post details: caption, hashtags, cover frame, YouTube title and an AI flag.
- Brands → Setup (`SetupTracker.tsx`, `setupNeeds.ts`) lists everything each social still needs before it can
  post.
- Series (`SeriesPanel.tsx`, `series.ts`, `seriesWriter.ts`) are stories across several videos, written by
  Grok, with consistent character pictures.

## 5. Accounts, emails, sign-ups

- **Verification inbox:** every sign-up uses `softwings25@gmail.com`. TikTok and X get a plus-address per brand,
  e.g. `softwings25+massagewithmia@gmail.com`. Instagram and YouTube can sit under the main login.
- **Developer accounts:** TikTok for Developers, Google/YouTube, X and Meta use the main email, with no
  plus-address. There is one per platform, not one per brand. They are tracked separately from brand accounts.
- **Rule: brand windows never fill the main Gmail or a developer account's password.** TikTok and X fill only
  the brand's own login. `usesMainLogin`, `wrongLogin` and `brandLogin` in `useBrowserPosting.ts` enforce this.
- Passwords are generated, saved in Credential Manager, backed up, viewable by Nate, and listed in the JSON
  export. Sign-in pages always open on the email/password form, prefilled. Never generate a password for the
  main Google login.
- Sign-up birthday is always 1983-06-05.
- Sign-up automation (`CreateAccountWizard.tsx`, `autofill.rs`, `docs/signup-flows.md`):
  - The app fills the forms. **Nate presses the final buttons and solves captchas himself.**
  - No detection evasion, no hidden or background browser automation, no virtual SMS numbers.
  - Verification codes show in a bottom-right popup with a Copy button (`InboxList.tsx`, `email.rs`,
    `gmail_session.rs`).
- Every brand has its own WebView2 data folder, `%LOCALAPPDATA%\com.socialmanager.desktop\posting\<brandId>`, so
  each brand stays signed in separately. `sign_in_state.rs` records who is signed in.

## 6. How each social posts

| Social | Method | State |
| --- | --- | --- |
| Instagram | Meta Graph API (`instagram.rs`, `instagram_login.rs`) | The Meta app is in Development mode, which is fine for accounts Nate manages. |
| Facebook Reels | Meta Graph API, posting to the brand's Page (`facebook.rs`, 0.29.0+) | Works: Massage with Mia posted. |
| TikTok | In-app browser window on TikTok's upload page (`posting.rs`); Nate presses Post | The API is on Sandbox keys until TikTok's review, which needs a demo video. |
| YouTube | In-app browser window on Studio's upload page; Nate presses Publish | The Google app is in Testing until the audit. |
| X | In-app browser window; Nate presses Post | The X API is pay-per-use with $0 credits, so the browser is used. X has posted. |

- **Browser posting** (`posting.rs` `POST_SCRIPT`):
  - It attaches the video and fills the caption and title.
  - It makes the cover from a chosen frame, sets TikTok's AI label, and sets YouTube's made-for-kids and
    altered-content answers.
  - It steps YouTube to Visibility and picks Public.
  - It never presses Post or Publish. It stops pressing anything once Nate clicks on the page himself.
- App review tracking: `appReviews.ts` and `ReviewNotice.tsx` watch the TikTok and Google review emails. Test
  mode badges show while reviews are pending.

## 7. Instagram and Facebook (standalone accounts)

- **Rule (Nate, 2026-11-22, since 0.34.0):** every brand's Instagram, Facebook, TikTok and X is its own
  standalone account with its own email (a plus-address of the base inbox) and generated password. None is tied
  to the main softwings25 account, to another brand's login, or to a Page in the SoftWings business portfolio.
- Because Meta's API only publishes to Professional Instagram accounts linked to a Page it manages, Instagram and
  Facebook post through their own sites in the brand's window, like TikTok and X (`postingMode.ts`:
  `API_UPLOADS` is empty). Instagram opens instagram.com and presses New post; Facebook opens
  facebook.com/reels/create. The post script attaches the video, steps through Next and fills the caption.
  Nate presses Share / Publish.
- Facebook sign-up opens facebook.com/r.php and fills first name, surname, birthday, email and password.
- The Meta API code (`instagram*.rs`, `facebook.rs`, Connect buttons) is kept for a social switched back to
  'api' in `postingMode.ts`. Meta app "SocialSpace", app id 1766190812180262.

## 8. AI

- **All AI uses xAI Grok**, with no Gemini. That covers the assistant, Suggest buttons, ghost-text, bios,
  series writing and brand pictures (`grok_ai.rs`, `src/assistant/grokClient.ts`, `ProfileImageStudio.tsx`).
  The key is the Grok video source's key (`video_sources::xai_key`).
- Video generation is provider-neutral (`video_gen.rs`, `video_sources.rs`), with Kling and Grok as sources.
